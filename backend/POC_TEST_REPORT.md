|-------|----------|---------|----------|--------------|----------------|

### 3.2 คุณสมบัติข้อมูลทดสอบ
- **วิชาคาบคู่ (Double Period):** วิชาแรกของแต่ละห้องเป็นคาบคู่ (2 คาบติดกัน)
- **วิชาพละ (PE):** วิชาที่ 3 ของแต่ละห้อง เป็นหมวดพลศึกษา
- **วิชาหนัก (Heavy):** วิชาที่ 1 และ 2 ถูกทำเครื่องหมายเป็นวิชาหนัก (S2: ควรอยู่ช่วงเช้า)
- **ครูควบภาระงานบริหาร:**
  - **T1 = ครูการเงิน (Finance):** ล็อกคาบว่าง พฤหัสบดี–ศุกร์ คาบ 5–8 (T4)
  - **T2 = ครูฝ่ายปกครอง (Discipline):** ล็อกคาบว่าง คาบ 1 และคาบสุดท้าย ทุกวัน (T5)
- **PE Hot Periods:** คาบ 7–8 ของทุกวัน (ช่วงบ่ายแดดร้อน — H11)

## 9. สถาปัตยกรรมที่ทดสอบ

### 9.1 โครงสร้างไฟล์
```
backend/
├── models.py          # Pydantic schemas (input/output)
├── solver.py          # OR-Tools CP-SAT solver engine
├── main.py            # FastAPI app + endpoints
├── generate_fixtures.py  # สร้างข้อมูลทดสอบ 3 ขนาด
├── test_solver.py     # สคริปต์ทดสอบอัตโนมัติ
├── schema.sql         # Database schema v3 (15 tables)
├── requirements.txt   # Python dependencies
└── fixtures/
    ├── school_small.json    # 3 ห้อง, 5 ครู, 15 LB
    ├── school_medium.json   # 6 ห้อง, 12 ครู, 48 LB
    └── school_large.json    # 12 ห้อง, 25 ครู, 120 LB
```

### 9.2 โมเดลตัวแปรตัดสินใจ (Decision Variable Model)

ใช้โมเดล **4D Boolean** ตาม `time_table.md`:
- `x[lesson_block_idx, day, period]` — สำหรับคาบเดี่ยว
- `pair[lesson_block_idx, day, period]` — สำหรับคาบคู่ (ครอบ p และ p+1)

### 9.3 กลยุทธ์ Pre-assignment
- คาบชุมนุม/ล็อก → ตัดตัวแปรออกก่อนสร้างโมเดล (ลด search space)
- ครูไม่ว่าง / ครู admin → ตัดตัวแปรออก
- พละในคาบร้อน → ตัดตัวแปรออก

## 10. ข้อสรุปและข้อเสนอแนะ

### 10.1 สรุปผล
1. **Solver ทำงานได้ดีเกินคาด** — ผลลัพธ์ OPTIMAL ในเวลา < 0.7s สำหรับขนาดใหญ่สุด (120 LB)
2. **Hard Constraints ทั้งหมดไม่มีการละเมิด** — H1 ถึง H11, T4, T5 ผ่านครบ
3. **Soft Constraints เป้าหมาย = 0** — Solver หาผลลัพธ์ที่ไม่มี penalty เลย
4. **Pre-assignment มีประสิทธิภาพ** — ลดจำนวนตัวแปรลงอย่างมีนัยสำคัญ
5. **API พร้อมใช้งาน** — ทุก endpoint ตอบสนองถูกต้อง

### 10.2 ข้อเสนอแนะขั้นต่อไป
1. **Frontend POC** — สร้าง UI สำหรับ user ลองใช้งาน (เลือก fixture → กดสร้าง → ดูตาราง)
2. **ทดสอบกับข้อมูลจริง** — นำข้อมูลโรงเรียนจริงมาทดสอบเพื่อยืนยันความเป็นไปได้
3. **เพิ่มขนาด Extra Large** — ทดสอบ 20+ ห้องเรียนเพื่อหาจุด break-even
4. **เพิ่ม Soft Constraint S4/S5** — Teacher Gap Minimization, Building Transit
5. **เริ่มพัฒนา Product MVP** — ใช้ผล POC เป็นแกนสำหรับ backend ของ product

### 10.3 ความเสี่ยงที่ประเมินได้
| ความเสี่ยง | ระดับ | สถานะ |
