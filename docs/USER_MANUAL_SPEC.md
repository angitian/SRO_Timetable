### 1.2 การจดจำหัวคอลัมน์อัตโนมัติ (Auto-mapping)

ระบบจับคู่หัวคอลัมน์กับฟิลด์ผ่าน **การ Normalize ข้อความ** (ตัดช่องว่าง/ขีดล่าง/ตัวพิมพ์เล็ก) แล้วเลือกแบบ 2 รอบ:

1. **รอบแรก:** จับคู่แบบตรงเป๊ะ (normalized เท่ากัน) เช่น `Lab_Periods` → `คาบแล็บ` ก่อน
2. **รอบสอง:** จับคู่แบบคลุมเครือ (fuzzy score ≥ 0.7) สำหรับฟิลด์ที่ยังไม่มี เช่น `จำนวนคาบต่อสัปดาห์` → `คาบ/สัปดาห์`

ชื่อคอลัมน์ที่ระบบรู้จัก (ไทย + อังกฤษ):

| ฟิลด์ | ชื่อคอลัมน์ที่รองรับ (ตัวอย่าง) |
|---|---|
| ชื่อครู | ชื่อครู, ครู, ผู้สอน, อาจารย์, ครูผู้สอน, ชื่อผู้สอน, teacher name, teacher, instructor |
| ครูผู้สอนร่วม | ครูที่ 2, ครูผู้สอนร่วม, ผู้สอนร่วม, ครูร่วมสอน, ผู้ช่วยสอน, ครูต่างชาติ, co-teacher, second teacher, teacher assistant |
| วิชา | วิชา, รายวิชา, กลุ่มสาระ, สาระ, วิชาเรียน, subject name, subject, course |
| ห้องเรียน | ห้อง, ชั้น, ห้องเรียน, ระดับชั้น, ชั้นเรียน, class, classroom, grade, room, section |
| คาบ/สัปดาห์ | คาบ, คาบ/สัปดาห์, จำนวนคาบ, ชม., ชม./สัปดาห์, คาบสอน, periods, hours, periods per week |

| คาบแล็บ | คาบแล็บ, คาบปฏิบัติการ, คาบแลป, คาบที่ใช้ห้องปฏิบัติการ, จำนวนคาบแล็บ, lab periods, practical periods |

### 1.3 เงื่อนไขพิเศษ: ครูร่วม / ห้องแล็บ / คาบคู่

**ครูผู้สอนร่วม (Co-teacher):**
- ถ้าระบุชื่อครูร่วม ระบบจะสร้าง record ครูใหม่ถ้ายังไม่มี
- คาบของวิชานั้น **นับภาระงานให้ครูทั้ง 2 คน** และ **กันไม่ให้ครูคนใดคนหนึ่งโดนจัดคาบอื่นชน** ในเวลาเดียวกัน
- ครูร่วมถูกนับรวมในการตรวจความจุ (Pre-flight) ด้วย

**การแยกคาบแล็บ (Lab split):** ระบบแยกวิชาเป็น 2 บล็อกอัตโนมัติเมื่อเข้าเงื่อนไขครบทุกข้อ:
- `คาบแล็บ > 0` และ มีชื่อ `ห้องปฏิบัติการ` และ `คาบแล็บ < คาบ/สัปดาห์`

| เงื่อนไข | ผลลัพธ์ |
|---|---|
| คาบแล็บ = 2, คาบ/สัปดาห์ = 5 (วิทย์) | แยกเป็น **บล็อกห้องเรียน 3 คาบ** + **บล็อกห้องแล็บ 2 คาบ** — ห้องแล็บถูกกันไม่ให้ซ้อนกับชั้นอื่นที่ใช้ห้องเดียวกัน |
| คาบแล็บ = 5 = คาบ/สัปดาห์ | **ไม่แยก** — ทุกคาบใช้ห้องปฏิบัติการ (ห้องแล็บนั้น) |
| ระบุห้องปฏิบัติการแต่ไม่ระบุคาบแล็บ | ใช้ห้องปฏิบัติการทั้ง 5 คาบ (ไม่แยก) |
| ระบุคาบแล็บแต่ไม่มีชื่อห้องปฏิบัติการ | **ไม่แยก** — คาบแล็บถูกละเลย ใช้ห้องเรียนปกติ |

**คาบคู่ (Double period):**
- วิชาที่เป็นคาบคู่ จะถูกจัดเป็น **คู่ติดกัน (คาบ p + p+1)** เสมอ
- ถ้าจำนวนคาบ/สัปดาห์เป็น **เลขคี่** (เช่น 3) ระบบจัดเป็น 1 คู่ + 1 คาบเดี่ยว
- ต่อวันจัดได้สูงสุด **1 คู่** (และถ้ามีคู่แล้ว อนุญาตคาบเดี่ยวเพิ่มได้อีกไม่เกิน 1 → รวมไม่เกิน 3 คาบ/วัน)
- คาบคู่ต้องมีคาบถัดไปเป็นคาบเรียน (ไม่สามารถลงท้ายก่อนพักเที่ยง/คาบสุดท้ายของวัน)

### 1.4 การจัดการข้อความไม่ตรงรูปแบบ (Normalization & Fallback)

- **ช่องว่างเกิน/ขีดล่าง:** ทุกเซลล์ถูก `.strip()` ก่อน และการเทียบชื่อคอลัมน์ตัดช่องว่าง+ขีดล่างออกทั้งหมด (เช่น `Lab_Periods` = `labperiods`)
- **ตัวเลขปนข้อความ:** `คาบ/สัปดาห์` ใช้ regex ดึง "ตัวเลขตัวแรก" ออกมา เช่น `"5 คาบ"` → 5; ถ้าไม่มีตัวเลข → ค่า default (1)
- **ชื่อห้อง → ช่วงชั้น:** ระบบแปลงชื่อห้องเป็น `grade_level` สำหรับใช้กับกฎ "วิชาเฉพาะช่วงเวลา/วัน" และไฟล์คาบพิเศษ:
  - `ป.1`–`ป.6` → 1–6, `ม.1`–`ม.6` → 7–12, `อ.1`–`อ.3` → −2–0
  - ชื่อห้องที่แปลงไม่ได้ → grade default = 7 (ม.1)
- **แถวว่าง:** แถวที่ทุกเซลล์ว่างถูกข้าม
- **แถวซ้ำกัน (Deduplicate):** แถวที่มี (ครู + วิชา + ห้อง + ห้องปฏิบัติการ + คาบคู่) เหมือนกันทุกคอลัมน์ ระบบถือว่า "พิมพ์ซ้ำ" แล้ว **รวมคาบเข้าด้วยกัน** พร้อมแจ้งเตือน `⚠ พบแถวซ้ำ N กลุ่ม: ระบบรวมคาบของแถวที่ซ้ำกันให้อัตโนมัติ`
  - > ถ้าต้องการแยกบล็อกจริง ๆ (เช่น วิชาเดียวกัน ห้องปกติ + ห้องแล็บ) ให้ใช้คอลัมน์ "ห้องปฏิบัติการ/คาบแล็บ" — ระบบไม่ merge บล็อกที่มีห้องต่างกัน
- **การ์ด (Garbage) ในช่องห้ามสอน:** ค่าเช่น `—`, `-`, `ไม่มี`, `ว่าง`, `none` ถูกตัดออก ไม่ถูกตีความเป็นคาบห้ามสอน
- **ขนาดไฟล์:** สูงสุด **10 MB** (เกิน → HTTP 413)

| แนะแนว / guidance | `guidance` |
| รด / rotc | `rotc` |
| อื่น ๆ | `other` |

**กลไกการตรึงคาบ (Fixed slots) และผลกระทบต่อความจุ:**

- **ระบุช่วงชั้น/ห้อง:** เฉพาะห้องที่ระบุถูกบล็อกที่ (วัน, คาบ) นั้น
- **เว้นว่างหรือเขียน "ทุกห้อง":** กลายเป็น **กิจกรรมรวมชั้น (assembly)** — **ทุกห้องทั้งโรงเรียน**ถูกบล็อกที่ (วัน, คาบ) นั้น (เช่น เคารพธงชาติ)
- **ครูผู้สอน (ครูผู้ดูแลรายชั้น):** ครูทุกคนในรายชื่อถูกห้ามโดนจัดคาบอื่นชนเวลานั้น และ**ภาระงานครูเพิ่ม 1 คาบ/สัปดาห์/ครู/กิจกรรม** (ไม่คูณจำนวนห้องที่ดูแล)
- **ผลต่อความจุ:** ทุกคาบที่ล็อก = ลดช่องว่างของห้องลง 1 ช่อง — หน้าจอจะ**เตือนก่อนบันทึก** ถ้าห้องใดใช้คาบเต็มแล้ว ("ห้องต่อไปนี้ใช้คาบเต็มแล้ว — เพิ่มกิจกรรมนี้จะจัดตารางไม่ได้") และ backend จะรายงาน `class_capacity_issues` (ดูข้อ 3.1)
- กิจกรรมที่ **วัน+คาบ+ห้องชนกับกิจกรรมเดิม** → เตือนและบันทึกไม่ได้จนกว่าจะแก้

> ⚠️ **ข้อควรระวัง:** ชื่อชั้น/ชื่อครูในไฟล์คาบพิเศษ **ต้องตรงกับข้อมูลที่นำเข้าแล้วในระบบ** (หลัง Normalize — ตัวพิมพ์เล็ก/เว้นวรรคไม่นับ) — ชื่อไม่พบจะถูกข้ามเงียบ ๆ พร้อมข้อความเตือนในหน้าพรีวิว ให้ตรวจพรีวิวก่อนกด "นำเข้า"

## 2. กฎและเงื่อนไขการคำนวณ (System Constraints & Logic)

ระบบใช้ **OR-Tools CP-SAT Solver** แบ่งกฎเป็น 2 ชั้น: **Hard Constraints** (ห้ามละเมิดเด็ดขาด — ถ้าขัด = จัดไม่ได้) และ **Soft Constraints** (น้ำหนัก penalty — ระบบพยายามเกลี่ยให้ดีที่สุด)

### 2.1 Hard Constraints (เงื่อนไขบังคับ)

| รหัส | กฎ | รายละเอียด |
|---|---|---|
| H1 | **ครูซ้อนคาบไม่ได้** | ครู 1 คน (รวมครูผู้สอนร่วม) ต้องไม่ถูกจัด 2 วิชาในเวลาเดียวกัน — ในโหมดหลายบล็อก (Schedule Blocks) ระบบตรวจ **เวลาจริงซ้อนทับกัน** (เช่น คาบที่ 4 ของบล็อก A ชนคาบที่ 3 ของบล็อก B) |
| H2 | **ห้องเรียนซ้อนไม่ได้** | ห้องเรียน 1 ห้องมีวิชาเดียวต่อคาบ |
| H3 | **ห้องแล็บ/ห้องพิเศษซ้อนไม่ได้** | ห้องที่มีการระบุ `room_id` (ห้องปฏิบัติการ/ห้องพิเศษ) ใช้พร้อมกัน 2 วิชาไม่ได้ — กันการชนของห้องแล็บที่หลายชั้นใช้ร่วมกัน |
| H4 | **จำนวนคาบครบทุกวิชา** | ทุกวิชาต้องได้จำนวนคาบตาม `คาบ/สัปดาห์` ครบ — โหมดปกติ (Phase A) เป็น Hard ระบบจะไม่คืนตารางที่ไม่ครบถ้าเป็นไปได้; ถ้าพิสูจน์แล้วว่าเต็มจริง ระบบสลับเป็น Soft (Phase B) และคืนตารางที่จัดได้มากที่สุด + คำอธิบายคาบที่เหลือ (ดู 3.3) |
| H5 | **จำกัดคาบต่อวันต่อวิชา** | วิชาเดี่ยว: อย่างน้อย 1 และไม่เกิน min(2, ceil(คาบ/สัปดาห์ ÷ จำนวนวัน)) คาบ/วัน (สูงสุด 2); วิชาคู่: ≤ 1 คู่/วัน (+ คาบเดี่ยวได้อีก ≤ 1 → รวม ≤ 3 คาบ/วัน) — บังคับให้กระจายวิชาไม่กองวันเดียว |
| H6 | **คาบปักหมุด/ตรึง (Pre-assignment)** | วิชาที่ถูกปักหมุด (is_fixed / fixed_slots) ต้องอยู่ที่ (วัน, คาบ) ที่ระบุเท่านั้น |
| — | **ภาระงานขั้นต่ำครู (min)** | ครูต้องได้คาบไม่น้อยกว่า `min_periods_per_week` (ถ้าตั้งค่า) |
| — | **ช่องห้ามสอนครู (unavailable)** | ช่อง `วัน-คาบ` ที่ครูระบุว่าไม่ว่าง → ห้ามจัดเด็ดขาด |
| T4 | **คาบว่างงานธุรการ (admin free)** | ช่องที่ครูต้องว่างเพื่อทำงานธุรการ (`admin_free_slots`) → ห้ามจัด |
| T5 | **ครูปกครอง (Discipline)** | ครูที่มีบทบาท "ปกครอง" ต้องว่าง **คาบที่ 1 (เช้า) และคาบสุดท้ายของวัน** |
| — | **ครูไม่เอาคาบแรก/คาบสุดท้าย** | `no_first_period` → ห้ามจัดคาบ 1; `no_last_period` → ห้ามจัดคาบสุดท้ายของวัน (ช่องที่เหลือจะลดลง — ระวังครูที่ภาระสูง) |
| — | **กิจกรรมรวมชั้น / กิจกรรมห้อง** | Fixed slots: คาบกิจกรรมรวมชั้นบล็อกทุกห้อง; กิจกรรมเฉพาะห้องบล็อกเฉพาะห้องนั้น |
| — | **ครูผู้ดูแลกิจกรรม** | ครูที่ดูแลกิจกรรม (class_teachers) ถูกกันไม่ให้โดนจัดคาบอื่นชนเวลาดูแล |
| — | **PE ห้ามคาบร้อน (hot periods)** | วิชาพลศึกษา (category = pe) ห้ามจัดในช่อง `pe_hot_periods` ที่กำหนด (เช่น คาบกลางวันที่แดดร้อน) |
| — | **ครูมีเวลาพักเที่ยง (multi-block)** | ในโหมดหลายบล็อก ทุกวันครูต้องมีคาบว่างอย่างน้อย 1 ช่องในช่วง **11:00–13:30** |

### 2.2 Soft Constraints & Preferences (พร้อมน้ำหนัก)

Soft constraints ไม่ทำให้ "จัดไม่ได้" — แค่เพิ่ม **น้ำหนัก penalty** ให้ solver หลีกเลี่ยง

| รหัส | กฎ | น้ำหนัก | รายละเอียด |
|---|---|---|---|
| S1 | **ไม่จัดวิชาเดิมติดวัน** | 5 ต่อจุด | วิชาเดียวกันไม่ควรอยู่คาบเดียวกันในวันติดกัน (กระจายสัปดาห์) |
| S2 | **วิชาหนักเน้นเช้า** | 10 (ประณีต) / 1 (อื่น) | วิชาที่ mark "วิชาหนัก" (คณิต/ไทย/อังกฤษ ฯลฯ) ควรอยู่ในคาบ 1–3; ถ้าโหมด Hard → วิชาหนักห้ามอยู่ช่วงบ่ายเด็ดขาด |
| S3 | **ไม่สอนเกิน N คาบติดต่อกัน** | 100 ต่อคาบเกิน | ครูไม่ควรสอนเกิน `max_consecutive_teaching` คาบรวด (ค่าเริ่มต้น 4, ปรับได้ 2–5 หรือ smart default 2–4 ตามภาระ) |
| — | **เกลี่ยภาระงานข้ามวัน** | 5 ต่อคาบนอกช่วง | ภาระครูแต่ละวันควรอยู่ในช่วง [ค่าเฉลี่ย±1] คาบ เพื่อไม่ให้วันไหนโหลดเกิน |
| — | **รวมคาบว่างครู (เฉพาะ Deep)** | 3 ต่อจุดเปลี่ยน | ลดคาบว่างกระโดด (มีคาบว่างคั่นกลาง) ให้คาบของครูเรียงติดกันมากขึ้น |
| — | **ว่างเช้า 1 คาบ + ว่างบ่าย 1 คาบ** | 50 ต่อครึ่งวันเต็ม | เช้า = คาบก่อนพักเที่ยงแรก, บ่าย = คาบหลังพักเที่ยงสุดท้าย; ถ้าโหมด Hard → ครูต้องมีคาบว่างทั้งเช้าและบ่ายทุกวัน (อาจทำให้จัดไม่ได้ถ้าครูแน่น) |
| — | **วิชาเฉพาะช่วงเวลา (เช้า/บ่าย)** | 8 ต่อคาบผิดครึ่งวัน | วิชาที่ตั้งไว้ "เน้นเช้า/เน้นบ่าย" (Subject Time Rules) ถูกปรับเมื่ออยู่ในครึ่งวันที่ไม่ต้องการ; Hard → บังคับ |
| — | **วิชาเฉพาะวัน (วางได้/ห้ามวาง)** | 8 ต่อคาบผิดวัน | กฎวัน: `forbidden_days` ชนะ `allowed_days` เสมอ; Hard → บังคับ |
| — | **ภาระงานสูงสุดครู (max)** | 10 ต่อคาบเกิน | ⚠️ **เป็นแค่คำเตือน ไม่ใช่ตัวตัดคาบ** — solver จัดคาบครบทุกวิชาก่อน แล้ว flag `load_status = "over"` ให้เห็นในหน้าภาระงาน ระบบ**ไม่ตัดคาบทิ้ง**เพื่อให้อยู่ในเพดาน |
| — | **คาบที่วางไม่ครบ (Phase B)** | **1,000,000** ต่อคาบ | เยอะกว่าน้ำหนักอื่นรวมกันทั้งหมด — ระบบให้ความสำคัญ "วางคาบให้ครบที่สุด" ก่อนคุณภาพการเกลี่ย (lexicographic) |

**การเรียงลำดับความสำคัญ (Lexicographic):** วางคาบครบ (1,000,000/คาบ) ≫ คาบติดต่อกัน (100) ≫ ว่างเช้า+บ่าย (50) ≫ วิชาหนักเช้า/งานสมดุล/เฉพาะช่วงเวลา (5–10) ≫ gap clustering (3)

### 2.3 โหมดของกฎ (off / soft / hard) — เงื่อนไขระดับระบบ (Global Conditions)

ทุกกฎหลักมี 3 โหมด (บางกฎมีแค่ off/soft) ตั้งได้ที่การ์ด **"เงื่อนไขระดับระบบ (Global)"** ในหน้า Step 3 (ภาระงานครู):

| กฎใน UI | ฟิลด์ (schedule_config) | โหมดที่รองรับ |
|---|---|---|
| ว่าง 1 คาบเช้า + 1 คาบบ่าย | `am_pm_free_mode` | off / soft / hard |
| หลีกเลี่ยงสอนเกิน N คาบติด | `max_consecutive_mode` + `max_consecutive_teaching` | off / soft / hard |
| ไม่จัดวิชาเดิมติดวัน (S1) | `subject_day_spacing_mode` | off / soft / hard |
| วิชาหนักเน้นเช้า (S2) | `heavy_morning_mode` | off / soft / hard |
| เกลี่ยภาระงานข้ามวัน | `workload_balance_mode` | off / soft |
| รวมคาบว่างครู (Deep) | `gap_clustering_mode` | off / soft |
| เพดานคาบเริ่มต้นของครู | `default_max_periods_per_week` | ตัวเลข (0–60) |

**โหมด Hard + preflight:** ก่อนรัน solver ระบบจะตรวจล่วงหน้า (Pre-flight) ว่า Hard rule ใด "พิสูจน์ได้ว่าเป็นไปไม่ได้" แล้วคืนข้อความไทยอธิบายทันที (เช่น วิชาหนักรวม 30 คาบ แต่ช่องเช้ามีแค่ 25) แทนที่จะรอ solver คืน INFEASIBLE เปล่า ๆ

**วิชาเฉพาะช่วงเวลา/วัน (Subject Time Rules):** เลือกวิชา → เช้า/บ่าย/ทั้งวัน → โหมด soft/hard → จำกัดเฉพาะช่วงชั้น (grade_levels) + กำหนด "วางได้เฉพาะวัน" หรือ "ห้ามวางวัน" (forbidden ชนะ allowed เสมอ)

**ระดับครู (ต่อคน):** ที่บัตรครูแต่ละคนตั้ง `no_first_period`, `no_last_period`, `max_consecutive_teaching` (0 = ใช้ค่า global), `spread_free_periods` (ว่างเช้า+บ่าย เฉพาะคน — ใช้เมื่อ global เป็น off), ภาระ min/max และช่องห้ามสอน

### 2.4 พารามิเตอร์ที่ปรับแต่งได้ (Configurable Parameters)

**โครงสร้างตาราง (Schedule Blocks — Step 2):**

| พารามิเตอร์ | ค่าเริ่มต้น | ช่วงที่รองรับ | หมายเหตุ |
|---|---|---|---|
| จำนวนวัน/สัปดาห์ | 5 | 1–7 (UI: 5, 6) | |
| จำนวนคาบเรียน/วัน | 8 (รวมพักเที่ยง) | 1–12 (UI: 6–10) | "จำนวนคาบเรียนต่อวัน" ใน UI = คาบเรียน **ไม่รวม**พักเที่ยง เช่น 7 คาบเรียน + พักเที่ยง = 8 ช่อง |
| ตำแหน่งพักเที่ยง | หลังคาบที่ 4 | คลิกสลับได้ทุกคาบ (UI เดิม) / กำหนด "หลังคาบที่ N" (Step 2) | รองรับพักเที่ยงได้หลายคาบ; ถ้าไม่มีพักเที่ยง ระบบแบ่งเช้า/บ่ายครึ่งหนึ่งสำหรับกฎเช้า-บ่าย |
| เวลาเริ่มคาบแรก | 08:30 | HH:MM | `start_time` ของบล็อก |
| ความยาวคาบเรียน | 50 นาที | 10–120 | `period_duration_mins` |
| ความยาวพักสั้น | 10 นาที | 5–60 | แทรกระหว่างคาบเรียนติดกันอัตโนมัติ (`auto_short_break`) — ปิดได้ให้คาบติดกัน |
| ความยาวพักเที่ยง | 50 นาที | — | `lunch_duration_mins` |
| คาบพิเศษ/วันต่างกัน | ทุกวันเหมือนกัน | `apply_to_all_days` / `periods_by_day` | กำหนดโครงสร้างคาบต่างกันในแต่ละวันได้ (เช่น วันพุธเลิกเร็ว) |
| คาบพักสั้นแทรกกลาง | — | เลขทศนิยม (3.5) | แทรก BREAK ระหว่างคาบโดยไม่เลื่อนเลขคาบเดิม |

**โครงสร้างตาราง (Schedule Config — โหมดเดิม):** `days_per_week`, `periods_per_day`, `lunch_periods` (รายการคาบพัก)

**Solver:**

| พารามิเตอร์ | ค่าเริ่มต้น | ช่วง | หมายเหตุ |
|---|---|---|---|
| `solver_time_limit_seconds` | 2.0 วินาที (API) | 0.5–600 | ควบคุมโดย preset ใน UI |
| `optimization_mode` | BALANCED | FAST / BALANCED / DEEP | FAST หยุดที่คำตอบแรก; DEEP เปิด gap clustering |

### 2.5 Solver Presets (หน้าจัดตาราง)

| Preset | เวลา | พฤติกรรม | เหมาะกับ |
|---|---|---|---|
| ⚡ เร็ว (FAST) | ~15 วิ | หยุดที่คำตอบแรก — ได้ตารางครบ ไม่คำนึงถึงการเกลี่ย | ข้อมูลไม่ซับซ้อน, ทดลอง |
| 🎯 สมดุล (BALANCED) | ~60 วิ | เกลี่ย soft constraints ให้ดีที่สุดภายในเวลา | แนะนำทั่วไป |
| 💎 ประณีต (DEEP) | ~120 วิ | คุณภาพสูงสุด + ลดคาบว่างครู (gap clustering) | ช่องว่างน้อย, ล็อกกิจกรรมเยอะ |
| ⏱️ กำหนดเวลาเอง | 15–600 วิ | เลือกเวลา + โหมด สมดุล/ประณีต | โรงเรียนใหญ่ เงื่อนไขเยอะ |

> 💡 **เมื่อจัดไม่ครบ:** ระบบแนะนำให้ใช้ preset **ประณีต (~2 นาที)** หรือ **กำหนดเวลาเอง (สูงสุด 10 นาที)** — โดยเฉพาะเมื่อหน้าตรวจสอบแจ้ง "ห้องใช้คาบพอดี (zero-slack)"

## 3. ข้อจำกัด ความจุ และ Edge Cases

### 3.1 สูตรการตรวจสอบความจุ (Capacity Check)

ระบบตรวจก่อนรัน solver (Pre-flight) ด้วยสูตรเดียวกับตัว solver เพื่อรายงานสาเหตุเป็นภาษาไทย:

**ความจุของห้องเรียน (Class capacity):**

```
available = (จำนวนคาบเรียน/วัน × จำนวนวัน/สัปดาห์) − คาบกิจกรรมที่ล็อกห้องนั้น − คาบกิจกรรมรวมชั้น
```

- ถ้า `คาบรวมของห้อง > available` → รายงาน `class_capacity_issues` (ห้อง X ต้องการ N คาบ แต่มีช่องว่าง M) — **ไม่บล็อกการจัด** ระบบยังคืนตารางที่จัดได้มากที่สุดพร้อมเตือน

**ความจุของครู (Teacher capacity):**

```
available = ช่องคาบเรียนทั้งหมด − unavailable_slots − admin_free_slots
            − คาบที่ครูดูแลกิจกรรม − คาบแรก/คาบสุดท้ายที่งด − คาบกิจกรรมที่ห้องที่ครูสอนถูกบล็อก
            − คาบพักเที่ยงสำรอง 1 ช่อง/วัน (โหมดหลายบล็อก)
```

- `ภาระรวม (รวมครูร่วม + คาบดูแลกิจกรรม) > max` → **เตือน "over"** (ไม่บล็อก)
- `ภาระสอน > available` → **บล็อก** (`over_available`) — จัดไม่ได้จริง
- `ภาระ < min` → **บล็อก** (`under_min`)
- โหมด Hard "ว่างเช้า+บ่าย": `ภาระ > วัน × (คาบ/วัน − 2)` → **บล็อก**

**ความจุห้องพิเศษ (Room capacity):** `คาบที่ใช้ห้องแล็บรวม > คาบเรียน/วัน × วัน − คาบกิจกรรมรวมชั้น` → **บล็อก**

**Fixed slot conflicts (บล็อก):** ปักหมุดวิชาไปชน ช่องครูไม่ว่าง / คาบพักเที่ยง / กิจกรรมรวมชั้น / กิจกรรมห้องตัวเอง / คาบที่ครูต้องดูแลกิจกรรม / คาบคู่ที่ไม่มีคาบถัดไป (`no_pair_slot`)

**Hard rule feasibility (บล็อก):** โหมด Hard ของ "วิชาหนักเน้นเช้า" / "วิชาเฉพาะช่วงเวลา-วัน" ที่คาบรวมเกินช่องที่วางได้ (เช่น วิชา Hard เน้นเช้า รวม 30 คาบ แต่ช่องเช้าทั้งสัปดาห์มีแค่ 25)

### 3.2 สาเหตุที่ผู้ใช้มักทำแล้วจัดตารางไม่ได้ (Infeasible) — ที่พบบ่อย

> ⚠️ **10 อันดับสาเหตุที่ทำให้ Solver หาคำตอบไม่ได้:**

1. **คาบรวมของห้องเกินช่องว่างทั้งสัปดาห์** — เช่น ห้องเรียน 7 คาบ/วัน × 5 วัน = 35 ช่อง แต่รวมวิชาทั้งหมด 38 คาบ (หักคาบกิจกรรมแล้วด้วย)
2. **ครูสอนเกินช่องว่างที่เหลือ** — ครูภาระ 25 คาบ แต่ล็อก unavailable/admin free/ดูแลกิจกรรมไปแล้วเหลือช่องว่างแค่ 20
3. **ล็อกคาบ (unavailable) ชนกับคาบที่ปักหมุดวิชา** — ล็อกช่องเดียวกับที่ปักหมุดไว้ → solver รับรู้ว่าช่องนั้นใช้ไม่ได้ แต่ปักหมุดบังคับให้ใช้ → ขัดแย้ง
4. **ล็อกคาบที่ครูตัวเองต้องดูแลกิจกรรม** — ครูคนนั้นเป็นผู้ดูแลกิจกรรมที่ (วัน, คาบ) นั้นอยู่แล้ว
5. **ตั้ง Hard rule เกินกำลัง** — "วิชาหนักเน้นเช้า = Hard" หรือ "วิชาเฉพาะวัน = Hard" โดยที่คาบรวมเกินช่องเช้า/วันที่เหลือ
6. **Hard "ว่างเช้า 1 + บ่าย 1" กับครูที่สอนแน่น** — ครูที่ต้องสอนเกือบเต็มวันไม่มีคาบว่าง 2 คาบ/วันให้
7. **ปักหมุด/ล็อกไปที่คาบพักเที่ยงหรือคาบกิจกรรมรวมชั้น** — คาบนั้นไม่ใช่คาบเรียน
8. **คาบคู่ไปจอดที่คาบสุดท้าย** — คาบคู่ต้องมีคาบถัดไปเป็นคาบเรียน (คาบสุดท้าย + พักเที่ยงต่อ = วางไม่ได้)
9. **กิจกรรมพิเศษล็อกซ้ำซ้อนจนห้อง/ครูเหลือช่องไม่พอ** — กิจกรรมรวมชั้นวันละ 2 คาบ × หลายกิจกรรม
10. **ระบุคาบ/วัน ไม่ตรงกับโครงสร้างบล็อก** — เช่น ปักหมุดคาบ 8 แต่บล็อกมีแค่ 7 คาบ หรือล็อกวันเสาร์ (ระบบรองรับแค่จันทร์–ศุกร์)

### 3.3 ความหมายของสถานะและรหัสข้อผิดพลาด

**สถานะ (SolverMetrics.status):**

| สถานะ | ความหมาย |
|---|---|
| `OPTIMAL` | พบตารางที่ดีที่สุดตามน้ำหนัก — ครบทุกคาบ |
| `FEASIBLE` | พบตารางที่ใช้ได้ (อาจเป็น Phase B = คาบไม่ครบ) |
| `INFEASIBLE` | พิสูจน์แล้วว่าเป็นไปไม่ได้ภายใต้เงื่อนไขปัจจุบัน (HTTP 422 พร้อม diagnostics เต็ม) |
| `UNKNOWN` | หมดเวลาก่อนหาคำตอบ (แนะนำเพิ่มเวลา) |

**ข้อความแจ้งเตือน (Diagnostics notes):**

- **"พิสูจน์แล้วว่าวางครบไม่ได้ภายใต้เงื่อนไขปัจจุบัน — คาบที่เหลือ X คาบไม่มีช่องที่ไม่ขัดกฎ (เช่น ครูต้องดูแลกิจกรรม/ติดสอนคลาสอื่น หรือห้องถูกกิจกรรมบล็อก)"** → Phase B ได้ OPTIMAL = ยืนยันทางคณิตศาสตร์ว่าเต็มจริง ดูรายละเอียดคาบที่เหลือ (unplaced blocks)
- **"ยังไม่พบตารางที่วางครบทุกคาบภายในเวลาที่กำหนด — นี่คือตารางที่วางได้มากที่สุด (ขาด X คาบ) แนะนำเพิ่มเวลาคำนวณ (preset ประณีต) ลดคาบล็อกกิจกรรม/วิชาในห้องที่เต็ม หรือวางเองที่ช่องว่างที่ระบบแนะนำ"** → แค่อยู่ในเวลาจำกัด ยังมีหวังถ้าเพิ่มเวลา
- **"Pre-flight ไม่พบสาเหตุชัด แต่ solver ยังคืน INFEASIBLE — อาจเป็นความขัดแย้งซับซ้อนระหว่าง hard constraints (เช่น ครูหลายคนแยกกันดูพอ แต่รวมในวันเดียวกันแล้วไม่พอ)"** → ตรวจข้อมูลซ้ำ/ผ่อนข้อจำกัด

**สาเหตุที่คาบวางไม่ได้ (UnplacedSlotInfo.reasons):**

| รหัส | แปลว่า |
|---|---|
| `class_occupied` | ห้องนั้นมีวิชาอื่นในคาบนี้แล้ว |
| `class_activity` | ห้องถูกกิจกรรมพิเศษล็อก (รวมชั้น/เฉพาะห้อง) |
| `teacher_busy` | ครู (หรือครูร่วม) ติดสอนวิชาอื่นคาบนี้ |
| `teacher_supervising` | ครูต้องดูแลกิจกรรมในคาบนี้ |
| `teacher_unavailable` | ครูไม่ว่าง / งานธุรการ / งดคาบแรก-สุดท้าย |
| `room_busy` | ห้องแล็บ/ห้องพิเศษถูกวิชาอื่นใช้ |
| *(ไม่มีเหตุผล)* | ช่องนี้วางได้ตามกฎทุกข้อ — solver แค่ยังไม่ได้ใช้ (หมดเวลา/ผลของคาบคู่) → **วางเองได้ที่ช่องนี้** |

**สถานะภาระงานครู (TeacherLoadSummary.load_status):** `ok` = อยู่ในเกณฑ์, `over` = เกิน max (คำเตือน — ระบบจัดครบแล้ว แค่ flag), `under` = ต่ำกว่า min

**รหัส conflict ของคาบปักหมุด (FixedSlotConflict.reason):** `teacher_unavailable`, `lunch`, `assembly`, `class_blocked`, `no_pair_slot`, `supervisor_unavailable`

**การเตือนฝั่งหน้าจอก่อนจัด (Verification Step):**
- **ห้องเกิน capacity** (แดง) — จัดไม่ได้แน่นอน → ต้องแก้ข้อมูล
- **ห้องคาบพอดีเป๊ะ (zero-slack ≤ 2)** (เหลือง) — จัดได้ แต่ solver ต้องใช้เวลานาน → แนะนำ preset ประณีต
- **ปัญหาการล็อกครู** (`over_available`, `supervisor_lock`, `pinned_lock`) — สาเหตุที่จัดไม่ได้หรือล็อกไม่ทำงาน แสดงก่อนกดจัดตาราง

### 3.4 เทคนิคการแก้ไขปัญหา (Troubleshooting)

> 🛠️ **จัดไม่ได้ (INFEASIBLE) ให้ทำตามลำดับ:**
> 1. ดูที่ **หน้า Verification (Step 4)** — ห้องสีแดง/เหลือง และรายการล็อกครูที่มีปัญหา
> 2. ถ้าเป็น "ห้องเกิน capacity" → **ลดคาบวิชาลง** หรือ **เพิ่มช่องว่าง** (เพิ่มจำนวนคาบ/วัน, ลดกิจกรรมที่ล็อกห้องนั้น)
> 3. ถ้าเป็น "ครู over_available" → **ลดภาระครู** หรือ **ปลดล็อกช่องห้ามสอน** (โดยเฉพาะ `no_first_period`/`no_last_period` กับครูที่ภาระ ≥ 20 คาบ)
> 4. ถ้าเป็น Hard rule → เปลี่ยนเป็น **Soft** ชั่วคราวเพื่อดูว่าจัดได้หรือไม่
> 5. ถ้ายัง INFEASIBLE → ลอง **ลบกิจกรรมพิเศษ/คาบปักหมุด** ออกทีละรายการเพื่อหาตัวที่ขัด
> 6. ถ้าจัดได้แต่ไม่ครบ → เปลี่ยน preset เป็น **ประณีต/กำหนดเวลาเอง** แล้วจัดใหม่

> 🛠️ **คาบที่เหลือ (missing) มีช่อง "วางเองได้"** — ระบบแสดงช่องที่ถูกกฎทุกข้อแต่ยังว่าง (`open_slots`) ให้ **ลากวางเองได้** ในหน้าตารางสอน (Step 5) โดยไม่ต้องรัน solver ใหม่

> 🛠️ **ล็อกครูแล้ว "ไม่ทำงาน"?** — ตรวจว่าล็อกช่องที่ห้องที่ครูสอนถูกกิจกรรมบล็อกอยู่แล้ว (กิจกรรมเฉพาะห้องที่ครูสอนครบทุกห้อง) หรือช่องที่ครูดูแลกิจกรรมเอง — ระบบจะแสดงเหตุผลในตารางล็อก (คาบสีเทา = บล็อกอยู่แล้ว ไม่ต้องล็อกซ้ำ)

> 🛠️ **วิชาคู่แล้วคาบเหลือคี่** — ระบบจัดเป็นคู่ + เดี่ยวปนกันเอง (เช่น 3 คาบ = 1 คู่ + 1 เดี่ยว) ถ้าอยากให้เป็นคู่ล้วน ให้ปรับจำนวนคาบ/สัปดาห์เป็นเลขคู่
